# Numpad 整板 PCB 设计文档

> 目标：把 nice!nano v2 模块 + numpad shield 的全部功能集成到单块 PCB，nRF52840 直接上板，不再使用 Pro Micro 模块。
>
> **当前方案**：沿用 nice!nano 开发板（不画整板）。本文档为整板设计参考，转为备用，将来紧凑化时启用。
>
> **第一参考**：`nicenano_NRF52840资料/原理图/nice！nano_v2-原理图_1.0.pdf` —— 最小系统与电源直接照抄。
> **芯片手册**：`nicenano_NRF52840资料/52840官方介绍/nRF52840_PS_v1.1.pdf`

## 1. 功能范围（默认全保留）

| 功能 | 说明 |
|------|------|
| 蓝牙 BLE | nRF52840 自带，2.4GHz 板载/陶瓷天线 |
| USB-C | 供电 + HID + DFU 刷写 |
| 锂电池充电 | 单节 LiPo，USB 时充电、拔线后蓝牙工作 |
| 6×4 矩阵 | 含编码器按下虚拟行 R5 |
| EC11 编码器 | A/B + 按下 |
| SSD1306 OLED | 0.91" 128×32，I2C |
| 电源开关 | 机械拨动开关控制电池通断 |

## 3. 模块设计

### 3.1 nRF52840 最小系统（最易翻车，照抄 nice!nano）

- **封装**：nRF52840 QFAA（QFN-100，7×7mm，0.4mm 间距），建议贴片，手焊极难
- **HFXO（高频晶振）**：32MHz + 2×12pF 负载电容，走线短、包地，蓝牙必须
- **LFXO（低频晶振）**：32.768kHz + 2×12pF，低功耗/RTC 唤醒必须
- **DCDC 电感**：约 10µH，接 DCC↔DEC4，启用内部 DCDC 降功耗（整板靠它省电）
- **去耦**：每个 VDD/VDDH 引脚就近 100nF，VDDH 加 4.7µF
- **射频前端**：ANT → PI 匹配网络（参考 Nordic DK 原理图，约 2 电感+1 电容）→ 50Ω 走线 → 板载 PCB 天线或陶瓷天线
- **复位**：RESET 引脚 + 10k 上拉 + 复位按键（双击进 DFU）
- **SWD 调试口**：SWDIO / SWCLK / RESET / GND / VTREF 引出测试点 —— **首次烧 bootloader 必须**，没有它板子无法启动

> 射频匹配、晶振负载电容的最终值以 nRF52840 PS 和 nice!nano v2 原理图为准。

### 3.2 电源

供电树（参考 nice!nano v2）：

```
USB-C 5V ─┬─> 充电 IC ─> 电池(3.0~4.2V) ─┬─> 电源开关 ─> VDDH
          │                              │
          └─> VBUS 检测(分压) ─> GPIO     └─> nRF52840 内部 DCDC ─> VDD(3.0V) ─> 系统 3.3V
```

- **充电 IC**：MCP73831 / BQ21040 / TP4054，单节锂电，500mA 左右
- **电池→系统**：nRF52840 的 VDDH 支持 2.1–5.5V，电池直接进 VDDH，内部 DCDC 降到 VDD，**无需外部 LDO**（nice!nano 做法）
- **VBUS 检测**：USB 5V 经分压（如 2:1）到 GPIO，用于检测插拔、充电唤醒
- **电源开关**：串在电池正极与 VDDH 之间
- **电池保护**（可选）：DW01 + FS8205A 过充过放保护

### 3.3 USB-C
- 接口：USB-C 16pin 或 24pin，5V（VBUS）+ D+/D- + GND
- D+/D- 直接连 nRF52840（内置 USB PHY，无需外部芯片）
- CC1/CC2 各串 5.1k 下拉到 GND（作 device）
- VBUS 加 ESD 保护（可选）

### 3.4 键盘矩阵
- 现有 6 行 × 4 列，直接 GPIO
- 每键串 1N4148（或 BAT54）防鬼影，二极管方向匹配 ZMK（现有 `col2row`：阳极接列、阴极接行，电流列->行）
- 整板不再受 Pro Micro 排针限制，引脚可按走线重排（见 §4）

标准 numpad 物理布局（PCB 排键参考）：

```
R0:  [ Num ][  /  ][  *  ][  -  ]
R1:  [  7  ][  8  ][  9  ][     ]
                            [  +  ]  ← + 2U 高（跨 R1-R2，轴在 R2C3）
R2:  [  4  ][  5  ][  6  ][     ]
R3:  [  1  ][  2  ][  3  ][     ]
                            [ Ent ]  ← Enter 2U 高（跨 R3-R4，轴在 R4C3）
R4:  [   0 (2U 宽)   ][  .  ][   ]
       ↑ 0 跨 C0-C1，轴在 R4C1，R4C0 为空位
```

- 2U 大键：+ 和 Enter 各 2U 高，0 为 2U 宽（均单轴，覆盖的另一个矩阵位置为空位）
- 已删 FN 键，编码器按下接管切层（音量/亮度），不再占独立键位
- 编码器旋钮物理位置由 PCB 决定，按下复用 R5 虚拟行（D10+D9）

### 3.5 编码器 EC11
- A/B 相各加 RC 去抖（100Ω + 0.1µF，或 0.1µF 到 GND）
- 公共脚接 GND
- 按下复用矩阵 R5 虚拟行（D10+D9 现有方案不变）

### 3.6 OLED SSD1306
- I2C：SDA + SCL + 3.3V + GND，4 脚焊接
- 与 nRF52840 同一 I2C 总线，地址 0x3C

### 3.7 Bootloader & SWD
- nRF52840 空片无 bootloader，**首次必须 J-Link 烧** `nicenano_NRF52840资料/BootLoader/nice_nano/dx_nice_nano_nrf52840_bootloader_s140_6.1.1.hex`
- 烧完后才能 USB 拖拽 uf2
- 工具：J-Link + nRF Connect Programmer（资料 `软件工具/` 内）

### 3.8 LED 指示（可选）
- 充电状态 LED（红/蓝，充电 IC 输出驱动）
- 蓝牙/系统 LED（GPIO 驱动）

## 4. 引脚分配（沿用 PINOUT.md，可直接用或按布线重排）

Zephyr 节点形式：`&gpio0 N` = P0.N，`&gpio1 N` = P1.N。

| 功能 | Pro Micro | nRF52840 | Zephyr 节点 |
|------|-----------|----------|-------------|
| 行 R0 | D20 | P0.29 | `&gpio0 29` |
| 行 R1 | D16 | P0.10 | `&gpio0 10` |
| 行 R2 | D14 | P1.11 | `&gpio1 11` |
| 行 R3 | D15 | P1.13 | `&gpio1 13` |
| 行 R4 | D18 | P1.15 | `&gpio1 15` |
| 行 R5（编码器按下）| D10 | P0.9 | `&gpio0 9` |
| 列 C0 | D9 | P1.6 | `&gpio1 6` |
| 列 C1 | D6 | P1.0 | `&gpio1 0` |
| 列 C2 | D5 | P0.24 | `&gpio0 24` |
| 列 C3 | D4 | P0.22 | `&gpio0 22` |
| EC11 A | D7 | P0.11 | `&gpio0 11` |
| EC11 B | D8 | P1.4 | `&gpio1 4` |
| OLED SDA | D2 | P0.17 | `&gpio0 17` |
| OLED SCL | D3 | P0.20 | `&gpio0 20` |
| VBUS 检测（新增）| — | 待分配 | 任一空闲 GPIO |
| UART（调试，可选）| D0/D1 | P0.8/P0.6 | `&gpio0 8`/`&gpio0 6` |
| 预留扩展 | D19/D21 | P0.2/P0.31 | `&gpio0 2`/`&gpio0 31` |

> 整板可重新分配引脚以优化走线，软件侧同步改 overlay 即可。

## 5. PCB 布局规则

- **MCU 居中**，射频区/天线放板边，**远离金属**（轴体、电池、螺丝都会挡信号）
- 32MHz 晶振紧贴 XC1/XC2，下方完整地平面
- RF 走线尽量短，控 50Ω 阻抗，下方不跨分割
- 去耦电容贴 MCU 同侧、就近引脚
- 充电 IC 靠近 USB-C 和电池接口
- 建议 **4 层板**（信号-地-电源-信号），射频/电源更稳；2 层省钱但走线要小心
- 关键地：晶振、射频、USB 各自就近回流

## 7. 固件适配（配套工作）

整板化后 overlay 需从 Pro Micro 抽象解耦，两条路线：

- **方案 A（最小改动，推荐先做）**：仍搭 `nice_nano` board（nRF52840 SoC 配置整板通用），把 overlay 里 `&pro_micro N` 换成 `&gpio0/&gpio1 N` 直连，`&pro_micro_i2c` 换成手写 I2C 节点，去掉 `requires: [pro_micro]`。构建命令不变。用于先验证自定义引脚可编译。
- **方案 B（原生整板）**：自建 ZMK board（`boards/arm/<板名>/`），矩阵/编码器/OLED 写进 board，构建变 `-b <板名>`，不再需要 shield。改动大但干净，等 PCB 定型后再做。

## 8. 推进路线

1. ✅ 功能范围确认（默认全保留）

3. ERC 检查

5. 打样小批量
6. J-Link 烧 bootloader → USB 烧固件验证
7. 固件：先方案 A 验证，PCB 定型后升级方案 B
